# 浏览器端 DICOM 查看器 · 详细需求清单

> 版本:v1.5  |  状态:五轮评审修订(技术缺口修复与功能补全)  |  更新日期:见 git 记录
> 定位:**纯前端单页应用(SPA)**,浏览器直接打开本地 DICOM 文件/文件夹(含子文件夹),数据全程不出浏览器。
> 技术栈:React + TypeScript + Vite + Cornerstone3D + vtk.js(用户已确认)

---

## 1. 项目概述

### 1.1 目标
构建一个运行在浏览器中的医学影像 DICOM 查看器,支持:

- 打开**单个 DICOM 文件**与**DICOM 文件夹(递归含子文件夹)**
- 2D 阅片:窗宽窗位、缩放、平移、翻页、旋转、反色
- **MPR 多平面重建**(轴向/冠状/矢状三平面联动,支持厚度模式)
- **3D 体绘制重建**(vtk.js)
- **信息显示可开关**(患者/检查/序列/像素信息覆盖文字)
- **测量**:长度、角度、ROI 区域灰度统计(均值/标准差/范围等)
- 增强功能:多序列对比、标注管理、DICOM SR 导出、基础分割
- **PACS 联网**:查询与拉取(DICOMweb 直连;传统 DICOM 经可选服务器侧网关,见 FR-13)
- **移动端适配**:手机与平板同等支持,触控手势 + 响应式布局(见 FR-14)

### 1.2 设计原则
1. **零安装、零上传(本地模式)**:所有 DICOM 数据在浏览器本地解析与渲染;URL 模式仅访问用户显式指定的地址。
2. **大体积可用**:500 层级 CT 数据集(约 500MB)可流畅浏览,不卡死 UI。
3. **医学测量可信**:长度/角度/ROI 统计基于 DICOM 像素间距(Physical Delta)计算,单位毫米,精度可校验。
4. **全浏览器一致**:Chrome / Edge / Firefox / Safari 功能等价;平台差异(文件夹句柄恢复、PWA 桌面安装)以等效方式补齐。
5. **移动端一等支持**:手机与平板同等适配,触控优先设计;移动端与桌面共享同一套核心代码(响应式布局 + 触控抽象),不单独维护移动版。

### 1.3 目标用户
- 临床医生、影像科医生(阅片、测量)
- 科研人员(灰度统计、3D 可视化、分割)
- 医学教学/学习人员
- 移动场景用户(查房、会诊、床旁阅片)

## 2. 术语表

| 术语 | 说明 |
|---|---|
| DICOM | 医学数字成像与通信标准,医学影像通用文件格式 |
| 传输语法 (Transfer Syntax) | 定义像素数据编码方式(未压缩/JPEG/JPEG2000/RLE 等) |
| 窗宽窗位 (WW/WL) | 控制灰度映射范围:窗宽=显示范围宽度,窗位=中心值 |
| VOI LUT / Modality LUT | DICOM 灰度变换:设备值→标准化值→显示值 |
| 像素间距 (Pixel Spacing) | 每个像素代表的物理尺寸(mm),测量计算的基础 |
| 序列 (Series) | 同一扫描协议下的一组连续图像 |
| 检查 (Study) | 一次检查产生的所有序列 |
| MPR | Multi-Planar Reconstruction,多平面重建(从体数据重切任意平面) |
| MIP / MinIP | 最大/最小密度投影(厚度模式下常用) |
| 体绘制 (Volume Rendering) | 对体数据整体渲染,常见于 3D 重建 |
| ROI | Region Of Interest,感兴趣区域(测量统计用) |
| HU | Hounsfield Unit,CT 值单位(水=0,空气=-1000) |
| SR / SEG | DICOM 结构化报告 / 分割对象,标准导出格式 |
| 重采样 (Resampling) | 将体数据按新间距/方向重新取样(MPR/体绘制的基础) |
| ImageId | Cornerstone 内部图像标识,加载入口 |
| IPP | Image Position Patient,图像空间位置(用于排序与重采样) |
| FrameOfReferenceUID | 帧参照 UID,标识同一患者坐标系;跨序列空间对齐/融合的前提判断依据 |
| SUV | Standardized Uptake Value,PET 标准摄取值(经体重/体表面积与注射剂量归一) |
| WADO-RS | DICOMweb 标准接口,通过 HTTP 获取 DICOM 实例/元数据 |
| QIDO-RS | DICOMweb 标准查询接口,通过 HTTP 检索患者/检查/序列 |
| STOW-RS | DICOMweb 标准存储接口,通过 HTTP 上传 DICOM(本期不做) |
| C-FIND / C-MOVE / C-ECHO | 传统 DICOM 网络服务:查询 / 拉取 / 连通性测试(浏览器无法直连,需网关桥接) |
| AE Title | DICOM 应用实体名,传统 DICOM 连接的身份标识 |
| DICOM 网关 | 服务器侧桥接组件:将传统 DICOM 协议转为 HTTPS/WebSocket 供浏览器访问(可选部署) |
| PWA | Progressive Web App,可安装到桌面的 Web 应用(需 HTTPS) |

## 3. 范围界定

### 3.1 范围内 (In Scope)
- 本地 DICOM 文件/文件夹打开与解析(递归子文件夹)
- 2D 阅片全功能(见 FR-3)
- MPR、3D 体绘制
- 测量(长度/角度/ROI 统计)与标注管理
- 信息覆盖文字开关与配置
- 多序列/多检查对比、图像融合
- 基础分割(阈值)+ 3D 叠加
- 截图、测量 JSON/CSV/DICOM SR 导出
- URL/HTTP 加载远程 DICOM(FR-1.15)
- PWA 离线安装(FR-10.6)
- PACS 查询与拉取:DICOMweb 直连 + 传统 DICOM 经服务器侧网关(FR-13)
- 移动端适配:手机/平板触控手势、响应式布局、移动端性能自适应(FR-14)
- 增强与兼容项:DICOM Overlay、DICOMDIR、Tag 浏览器、层滑块、ROI 直方图、PET SUV、全屏模式等(FR-1.16/1.17、FR-2.10、FR-3.18/3.19、FR-5.17、FR-9.6)

### 3.2 范围外 (Out of Scope,本期不做)
- 上传/发送到 PACS(STOW-RS / C-STORE)——本期仅只读(查询+拉取)
- DICOM 打印(Print SCU)
- PACS 工作清单 (Modality Worklist)
- 云 PACS / 托管服务深度集成
- 诊断级认证(不追求 FDA/CFDA 医疗器械认证)
- 报告系统、AI 辅助诊断
- 复杂分割(深度学习分割、多器官分割)
- 放射剂量管理、工作清单 (Worklist)
- 移动端原生 App(React Native / Flutter 原生壳);**浏览器移动端为正式适配目标**(手机+平板同等,见 FR-14)

## 5. 界面布局(概要)

```
┌────────────────────────────────────────────────────────────────┐
│ 顶部工具栏:打开文件 | 打开文件夹 | 布局 | 工具(WW/L/A/R/O/缩放/平移) │
│             | 播放 | MPR | 3D | 信息开关 | 截图 | 设置              │
├──────────┬─────────────────────────────────────┬───────────────┤
│ 左侧面板  │        视口区(1×1/2×2/3×3…)          │ 右侧面板       │
│ 序列树    │        每个视口含覆盖文字              │ 标注列表       │
│ 缩略图    │                                     │ 序列详情       │
│ 搜索      │                                     │ 统计数值       │
├──────────┴─────────────────────────────────────┴───────────────┤
│ 底部状态栏:当前序列信息 | 光标坐标 | 灰度值 | WW/WL | 缩放比例       │
└────────────────────────────────────────────────────────────────┘
```

- MPR 模式:视口区切换为 3 平面(或 2D+3D 混合)布局模板。
- 3D 模式:视口区为 3D 视口(可带一个 2D 参照视口)。
- PACS 模式:工具栏"PACS"入口打开查询面板(服务器选择 + 检索条件 + 结果表格);拉取结果进入左侧序列树(带"远程"来源标记)。
- 移动端:面板折叠为抽屉/底部弹层,工具栏图标化,视口全屏,触控手势操作(见 FR-14)。

### 7.2 分层架构

```
┌─────────────────────────────────────────────────────────┐
│ UI 层:React 组件(工具栏/序列树/视口容器/标注面板/设置)      │
├─────────────────────────────────────────────────────────┤
│ 状态层:zustand store(序列/视口/标注/设置)                 │
├──────────────────────┬──────────────────────────────────┤
│ 交互层:Cornerstone3D Tools(工具注册/激活/快捷键)          │
├──────────────────────┼──────────────────────────────────┤
│ 渲染层:Cornerstone3D(2D/MPR) | vtk.js(3D/分割)           │
├──────────────────────┼──────────────────────────────────┤
│ 数据层:图像缓存(LRU)/体数据构建/标注模型/分割掩膜          │
├──────────────────────┼──────────────────────────────────┤
│ 解析层(Web Worker):dicom-parser 元数据/像素解码/传输语法    │

└─────────────────────────────────────────────────────────┘
```

### 7.3 关键设计决策

1. **imageId 协议**:自定义 `dcm-file://` scheme,loader 从 FileSystemFileHandle/ArrayBuffer 直接解码,避免磁盘 IO 中间层。
2. **解析与解码在 Worker**:主线程只做渲染与交互;元数据解析、JPEG2000 等重解码全部在 Worker 池,UI 零阻塞。
3. **体数据构建**:MPR/3D 需要 Volume 时,按 IPP 重采样为等间距三维数组(Web Worker 中构建),构建进度可显示;超大体积(>1GB)提示或拒绝(本期上限约 1GB)。
4. **内存策略**:图像缓存 LRU + 最大缓存值可配置;切换序列即释放不可达缓存;3D GPU 纹理随视口销毁释放。
5. **测量统计用原始值**:ROI 统计基于 Modality LUT 后的原始像素值(如 HU),与窗宽窗位显示无关——需求 FR-5.7 已明确,实现时防止误用显示 LUT。
6. **兼容策略(全浏览器)**:Chromium 用 showDirectoryPicker(支持句柄恢复);Firefox/Safari 用 webkitdirectory 与文件夹拖拽(一等支持路径);均保留多文件选择兜底入口。
7. **版本锁定**:Cornerstone3D 与 vtk.js 生态迭代快,package.json 锁定精确版本,升级走 MR。
8. **PACS 接入分层**:浏览器只直连 HTTP 系协议(DICOMweb);传统 DICOM 一律经服务器侧网关(可选组件);imageId 使用 `dicomweb://` 与 `gateway://` scheme;远程序列与本地序列共用同一套缓存与内存策略(NFR-4)。
9. **触控优先设计**:交互层统一抽象"指针+触控"事件(Cornerstone3D Touch 工具族),UI 组件按断点响应式,桌面与移动端共用一套核心代码与工具状态,避免双套实现。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| File System Access API 在 Firefox/Safari 不可用 | 文件夹打开受限 | webkitdirectory 与拖拽作为一等支持路径(全浏览器完整支持决策);明确提示功能差异(句柄恢复不可用) |
| 远程 URL 加载受 CORS 限制 | 跨域 DICOM 拉取失败 | 文档说明服务端需配置 CORS 头;提供同源静态服务器示例;WADO-RS 需服务端支持 CORS |
| Safari PWA 支持不完整(无独立安装/后台同步) | 离线体验差异 | 以"添加到主屏幕"作为 Safari 等效路径;功能不依赖后台同步能力 |
| JPEG2000/JPEG-LS 解码慢 | 打开慢 | wasm 解码器(OpenJPEG/CharLS)Worker 解码;进度提示;HTJ2K 列为 P2 |
| 大体积数据集内存溢出 | 崩溃 | LRU 缓存上限、低内存模式、>1GB 提示;体数据构建走 Worker 并可取消 |
| vtk.js 体绘制在核显上帧率低 | 体验差 | 质量档位、渐进渲染;默认中档 |
| Cornerstone3D 版本 API 变动 | 升级成本 | 锁定版本;核心逻辑包一层适配层 |
| 多帧/彩色/特殊传输语法样本不足 | 兼容缺口 | 建立测试 DICOM 样本库(公开数据集:TCIA 等)持续回归;建设任务归属里程碑 M7 |
| 测量数值被质疑 | 信任问题 | 双精度计算;与 ImageJ/OsiriX 交叉验证;文档化计算公式;显示单位明确 |
| 视图旋转/翻转后标注错位 | 测量可信度受损 | 标注坐标随视图变换矩阵同步(FR-5.10);变换时校验标注几何,异常时提示重新绘制 |
| 医院 PACS 无 DICOMweb 接口 | 无法直连 | 网关模式适配传统 DICOM(FR-13.10);提供网关部署文档;DICOMweb 为主路径 |
| 医院网络策略 / CORS 限制 | 拉取失败 | 网关与 PACS 同内网部署规避 CORS;DICOMweb 需服务端配 CORS;文档说明两种路径 |
| HTTPS 应用请求 http 远程源被混合内容拦截 | PACS/DICOMweb 无法拉取 | 远程数据源强制走 HTTPS;网关支持 TLS 终结并提供自签证书信任指引(FR-13.10);错误提示含修复指引(FR-13.9、AC-36) |
| 大检查拉取撑爆内存 | 崩溃 | 按序列分批拉取、帧懒加载、受 NFR-4 缓存上限约束、低内存模式 |
| 认证方式多样(证书/SSO) | 接入受阻 | 支持 Bearer Token/Basic;证书类认证建议经网关处理;文档列兼容矩阵 |
